# OpenClaw 三个案例 Skill 使用诊断矩阵

文档性质：诊断文件。本文基于三个已形成案例包或阶段性归档的 run 产物统计 skill 使用情况；不新增案例事实，不改变 report basis。

> 说明：本文是原始使用台账。关于三个案例是否需要重跑、哪些未使用 skill 属于正常、哪些未使用暴露能力缺口，以及后续如何在不硬编排议程的前提下提高 skill uptake，见 `docs/diagnostics/openclaw-case-rerun-and-skill-uptake-audit.md`。

## 统计口径

1. “执行”来自各 run 的 `runtime/audit_ledger.jsonl` 中 `event_type=skill-execution` 的记录。
2. “skill-labeled artifact”来自 JSON 产物中的显式 `skill` 字段；这类产物说明该能力已经形成输出，即使 audit ledger 没有保留对应执行事件。
3. “仅见 preflight”表示该 skill 被做过权限/参数检查，但未形成执行记录。
4. “信号库有导入/继承记录”表示当前 run 的 `analytics/signal_plane.sqlite` 中存在由该 `source_skill` 产生的 normalized signals，但本 run audit ledger 未显示该 fetch skill 的直接执行；多见于继承、导入或历史数据复用。
5. role surface / skill registry 中仅被暴露的技能不计为“使用”。
6. `exit-nonzero`、`invalid-json`、`timeout` 等失败结果保留在表格中；失败尝试也是使用情况的一部分。

## 总体诊断

1. NYC smoke 和 Colorado River 已经跑通了“取证/归一化 -> DB 查询 -> 可选舆情分析 -> report basis -> narrative report”的较完整链路。
2. Colorado River 中大量 GDELT、YouTube、USGS、Open-Meteo 信号表现为“信号库有导入/继承记录”，说明其最终 rerun 主要使用既有或导入数据，再在 round-005 补 USBR RISE / Federal Register / USBR 项目记录。
3. PM2.5 NAAQS 跑通了 fetch / normalize / attachment route / report，但没有跑出 formal candidate audit、formal issue classification、public discourse corpus/aggregation/summary 等分析链路；这是其报告弱、样本小的直接程序原因。
4. 表中“未见使用”的 skill 不等于无用；它们可能是新能力、备用能力或未被该三个案例触发的能力。
